# Three supplied template conversions

This secondary test asks a student-facing question different from the original audit-and-generation benchmark. The original benchmark and its tie remain in the release record. The new test was designed after observing that tie. Decisions and scoring below are fixed before running any contestant on this secondary corpus.

Each trial receives three independently varied, synthetic template packages derived from the synthetic campus package in the first benchmark. No previous solver response is supplied. Alpine is a Letter DOCX, Bay is an A4 DOTX and Ridge is a landscape DOTX. Each has a distinct body style, section geometry, header text, body instructions, title and author slot location, embedded media and retained template wording. The authors, student numbers, titles and institutions are invented. The packages exercise ordinary editable Word placeholders, including runs split by Word, tables and headers. These are supported student workflows, not a representative sample of all school word processors.

All arms receive identical instructions and inputs. Each must create three editable, individually named blind-review Word documents while preserving the particular template. The task asks for documents only. It does not ask contestants to develop a reusable script. In assisted arms the unmodified 0.2.0 production skill is made available; bare arms have the same host, standard programming tools and time. There are three fresh matched pairs, in bare/assisted, assisted/bare, bare/assisted order. The three pairs may run concurrently; their wall times are descriptive. Sessions use Codex CLI 0.169.0, gpt-6.1-sol, low reasoning effort, workspace-write sandbox, disabled model web search/plugins/memories/host skills, a 600-second cap per arm and separate empty workspaces. Both sides share the standard host instructions. No candidate receives this protocol or the judge.

Each document earns four independent binary scores: (1) a readable macro-free DOCX package with a document content type and an internal office-document relationship; (2) all visible mapped titles, degrees and identity slots are filled in their original paragraphs, preserving visible labels; (3) identity data are absent in XML properties, attributes and run-concatenated paragraphs and the original identity placeholders are gone; (4) the underlying template's non-target document text, section configuration, live field instructions, run styles, tables, styles, headers, footers and media are preserved. The last criterion permits XML prefix/serialization changes, merging/splitting equivalent plain text runs and ordinary changes in document metadata. A readable file can receive partial credit. Inputs must keep their original digests. Total quality is 12 points per run.

The preregistered primary endpoint for **this** secondary task is new document-transformation code needed from the model. A blind, independently checked source inventory covers executed scripts, patch-created files and inline shell code; protocol counts *distinct newly authored normalized nonempty source lines that implement or invoke low-level DOCX/ZIP/XML transformation*, including definitions and control flow of the transformation routine. Calling a supplied document-level CLI, passing its arguments, input enumeration and read-only verification are not counted as new transformation code. A separately authored helper that generically reads/writes a DOCX package, XML editing operations and ZIP/XML rewrite calls count. Empty lines, comments, pure checks and solving prose do not. Duplicate executions of identical code count once. An implementation-effort advantage requires all six runs to deliver three files, the assisted median quality to equal or exceed the bare median, a reduction of at least 50% in median new transformation lines, and at least 8 fewer lines in at least two matched pairs. A zero means no document-transformation implementation was invented in that run. It says nothing about how easy the underlying existing skill was to develop.

Additional, distinct outcomes: a quality advantage requires at least two additional correct checks in at least two of three pairs and no median regression; a time or tool-call advantage requires at least 30% lower median successful elapsed time or at least 30% fewer median tool events with no median quality loss; a response-token advantage requires at least 25% lower median model-reported output tokens with no median quality loss. Reusability records whether one unchanged transformation implementation (preexisting or new) was actually applied to all three supplied templates, with variations limited to paths, field data and arguments. Report raw source inventories, counts, all three pairs and relevant limits even when thresholds fail. No further endpoint can replace these published decisions.
